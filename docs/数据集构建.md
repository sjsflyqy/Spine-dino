### 三、VinDr-SpineXR---10466张---多部位正侧位
#### 1.概述
适合增加第三个下游任务

VinDr-SpineXR包含10,466张脊柱X线，来自5000个检查，由放射科医生标注了7类异常及对应病灶框。数据通过PhysioNet提供，但属于受限或认证访问，需要注册、完成相应要求后申请。

适合你做什么

> 7种脊柱病变的多标签分类，外加互斥的 `No finding` 状态。
>

##### 数据集实际情况
官方已经划分为：

| 集合 | Study 数 | 图像数 | 标注行数 |
| --- | ---: | ---: | ---: |
| Train | 4,000 | 8,389 | 19,550 |
| Test | 1,000 | 2,077 | 4,748 |


本地文件数量与标注完全对应：

+ `train_images`：8,389 个 DICOM
+ `train_png`：8,389 个 PNG
+ `test_images`：2,077 个 DICOM
+ `test_png`：2,077 个 PNG

官方 train/test 之间：

+ 重复 `study_id`：0
+ 重复 `image_id`：0

因此官方测试集隔离是干净的，建议不要重新混合。

##### 8个标签
标签为：

1. `Osteophytes`
2. `Disc space narrowing`
3. `Foraminal stenosis`
4. `Spondylolysthesis`
5. `Vertebral collapse`
6. `Surgical implant`
7. `Other lesions`
8. `No finding`

但是同一张影像可以同时具有多个病变。例如可以同时存在骨赘和椎间隙狭窄。训练集中有：

+ 1,055 张多病变图像
+ 4,260 张仅 `No finding`
+ 4,129 张至少有一种病变
+ 没有同时标注 `No finding` 和病变的冲突图像

所以不应使用普通八分类的 Softmax + CrossEntropy。推荐：

+ 输出7个病变概率
+ 使用 sigmoid
+ 损失使用 BCEWithLogitsLoss、Asymmetric Loss 或 focal BCE
+ `No finding` 可以定义为7种病变全部为阴性

也可以保留第8个 `No finding` 输出，但要增加一致性约束，避免模型同时预测“无异常”和“存在病变”。

##### 类别分布明显不平衡
训练集按唯一图像统计：

| 标签 | 图像数 |
| --- | ---: |
| No finding | 4,260 |
| Osteophytes | 3,575 |
| Disc space narrowing | 602 |
| Other lesions | 333 |
| Foraminal stenosis | 271 |
| Surgical implant | 257 |
| Spondylolysthesis | 257 |
| Vertebral collapse | 157 |


因此不能只报告 accuracy。应报告：

+ 每类 AUROC
+ macro AUROC
+ 每类 AUPRC
+ macro AUPRC
+ macro-F1
+ sensitivity/specificity
+ 95%置信区间

尤其要重视 AUPRC，因为稀有类别只有一两百张。

##### 最推荐的划分方案
方案A：最实用、最标准

保留官方 test 完全不动：

```latex
官方 Train：4,000 studies / 8,389 images
├── 用于自监督预训练（忽略标签）
├── Downstream Train：约80%的 study
└── Downstream Validation：约20%的 study

官方 Test：1,000 studies / 2,077 images
└── 只用于最终测试，绝不参加预训练和调参
```

这里“预训练使用下游训练图像但不使用标签”是合理的，不构成测试泄漏。关键是官方 test 的任何图像不能进入预训练。

下游 train/validation 应当：

+ 按 `study_id` 划分，不能按 `image_id`
+ 使用多标签分层划分
+ 同一 study 的全部图像只能处于一个集合
+ 建议大约 80:20，即：
    - downstream train：约3,200 studies
    - validation：约800 studies
    - official test：1,000 studies

这是我最推荐的主实验协议，因为数据利用率最高。

##### 这个数据集还可以做检测任务
由于 CSV 中有：

+ `xmin`
+ `ymin`
+ `xmax`
+ `ymax`
+ `lesion_type`
+ `rad_id`

它不仅支持多标签分类，还可以做：

1. 图像级多标签分类
2. 7类病变目标检测
3. 病变定位
4. 分类与检测联合任务

而且每个框带有 `rad_id`，说明涉及3名放射科医生的标注。正式构建标签时需要制定读片者融合规则，例如：

+ 任一医生标注即阳性
+ 至少两名医生一致才阳性
+ 保留软标签：阳性医生数/3
+ 检测框使用 IoU 聚类后融合

对于分类 baseline，可以先采用“任一医生标注即图像阳性”，但论文级实验建议增加多数投票或软标签对照。

## 数据处理
### 一、预训练数据构建
#### 1.dicom数据和tiff数据转为png图像
```powershell
from __future__ import annotations

import csv
import os
from collections import Counter
from pathlib import Path
from typing import Optional

import numpy as np
import pydicom
from PIL import Image
from tqdm import tqdm

try:
    # 兼容多数 pydicom 版本
    from pydicom.pixel_data_handlers.util import apply_modality_lut

    # 新版 pydicom 的备用导入路径

# ============================================================
# 1. 路径配置：修改为你自己的目录
# ============================================================

INPUT_FOLDER = Path(r"H:\Hospital_data\nanning3\图像文件")
OUTPUT_FOLDER = Path(r"H:\Hospital_data\nanning3\img_new")

# 转换日志保存位置

# ============================================================

# 百分位灰度拉伸范围。
# 对大多数脊柱 X 线可先使用 0.5 和 99.5。
LOWER_PERCENTILE = 0.5
UPPER_PERCENTILE = 99.5

# True：保留输入目录的相对文件夹结构。
# False：所有 PNG 放在同一个目录，并把相对路径写入文件名，避免重名。
PRESERVE_FOLDER_STRUCTURE = False

# 是否覆盖已经存在的 PNG。
# 建议首次转换到新的输出目录，并保持 True。
OVERWRITE_EXISTING = True

# PNG 压缩等级：0 最快、9 最省空间。
# 压缩不会影响图像质量；3 通常速度和体积比较均衡。
PNG_COMPRESSION_LEVEL = 3

# 是否使用 force=True 强制读取缺少标准文件头的 DICOM。
FORCE_READ_DICOM = True

# 遇到多帧 DICOM 时：
# "skip"：跳过并记录；
# "first"：只转换第一帧。
MULTIFRAME_POLICY = "skip"

# 支持的 DICOM 文件扩展名。
# 若医院文件全部为 .dcm，保持默认即可。
DICOM_SUFFIXES = {".dcm", ".dicom"}


def find_dicom_files(input_root: Path) -> list[Path]:
    """递归查找 DICOM 文件。"""
    files: list[Path] = []

    for path in input_root.rglob("*"):
        if path.is_file() and path.suffix.lower() in DICOM_SUFFIXES:
            files.append(path)

    files.sort()
    return files


def get_output_path(
    dicom_path: Path,
    input_root: Path,
    output_root: Path,
) -> Path:
    """
    生成对应 PNG 的输出路径。

    PRESERVE_FOLDER_STRUCTURE=True：
        输入：图像文件/20230123/ABC.dcm
        输出：img_new/20230123/ABC.png

    PRESERVE_FOLDER_STRUCTURE=False：
        输入：图像文件/20230123/ABC.dcm
        输出：img_new/20230123__ABC.png
    """
    relative_path = dicom_path.relative_to(input_root)

    if PRESERVE_FOLDER_STRUCTURE:
        return (output_root / relative_path).with_suffix(".png")

    relative_without_suffix = relative_path.with_suffix("")
    filename_parts = relative_without_suffix.parts
    flat_filename = "__".join(filename_parts) + ".png"
    return output_root / flat_filename


def build_valid_mask(
    raw_pixels: np.ndarray,
    ds: pydicom.dataset.FileDataset,
) -> np.ndarray:
    """
    构建有效像素掩码，排除：
    1. NaN 或 Inf；
    2. PixelPaddingValue；
    3. PixelPaddingRangeLimit 指定的填充值范围。

    注意：PixelPaddingValue 属于原始存储像素域，
    因此必须在应用 RescaleSlope/RescaleIntercept 之前处理。
    """
    raw_float = raw_pixels.astype(np.float64, copy=False)
    valid_mask = np.isfinite(raw_float)

    if not hasattr(ds, "PixelPaddingValue"):
        return valid_mask

    try:
        padding_value = float(ds.PixelPaddingValue)
    except (TypeError, ValueError):
        return valid_mask

    if hasattr(ds, "PixelPaddingRangeLimit"):
        try:
            padding_limit = float(ds.PixelPaddingRangeLimit)
            lower = min(padding_value, padding_limit)
            upper = max(padding_value, padding_limit)
            valid_mask &= (raw_float < lower) | (raw_float > upper)
        except (TypeError, ValueError):
            valid_mask &= raw_float != padding_value
    else:
        valid_mask &= raw_float != padding_value

    return valid_mask


def select_single_frame(
    pixels: np.ndarray,
    ds: pydicom.dataset.FileDataset,
) -> np.ndarray:
    """
    将像素数据整理为单张二维灰度图。

    脊柱 CR/DR 通常是二维数组。
    对多帧数据，根据 MULTIFRAME_POLICY 决定跳过或取第一帧。
    """
    samples_per_pixel = int(getattr(ds, "SamplesPerPixel", 1))
    number_of_frames = int(getattr(ds, "NumberOfFrames", 1) or 1)

    if samples_per_pixel != 1:
        raise ValueError(
            f"检测到 SamplesPerPixel={samples_per_pixel}，"
            "当前脚本只处理单通道灰度 DICOM。"
        )

    if number_of_frames > 1:
        if MULTIFRAME_POLICY == "first":
            if pixels.ndim < 3:
                raise ValueError(
                    f"NumberOfFrames={number_of_frames}，"
                    f"但像素维度异常：{pixels.shape}"
                )
            pixels = pixels[0]
        else:
            raise ValueError(
                f"检测到多帧 DICOM：NumberOfFrames={number_of_frames}，已跳过。"
            )

    pixels = np.squeeze(pixels)

    if pixels.ndim != 2:
        raise ValueError(f"不支持的像素维度：{pixels.shape}")

    return pixels


def normalize_dicom_to_uint8(
    ds: pydicom.dataset.FileDataset,
    lower_percentile: float = LOWER_PERCENTILE,
    upper_percentile: float = UPPER_PERCENTILE,
) -> tuple[np.ndarray, dict[str, object]]:
    """
    将 DICOM 转为标准 8-bit 灰度图。

    处理流程：
    1. 解码像素；
    2. 处理单帧灰度数据；
    3. 排除 PixelPaddingValue；
    4. 应用 Modality LUT / RescaleSlope / RescaleIntercept；
    5. 使用百分位灰度拉伸；
    6. 处理 MONOCHROME1 反色；
    7. 输出 uint8 PNG 所需数组。
    """
    if not (0.0 <= lower_percentile < upper_percentile <= 100.0):
        raise ValueError(
            "百分位参数必须满足："
            "0 <= LOWER_PERCENTILE < UPPER_PERCENTILE <= 100"
        )

    raw_pixels = ds.pixel_array
    raw_pixels = select_single_frame(raw_pixels, ds)

    valid_mask = build_valid_mask(raw_pixels, ds)

    # 应用 RescaleSlope / RescaleIntercept 或 Modality LUT。
    modality_pixels = apply_modality_lut(raw_pixels, ds)
    image = np.asarray(modality_pixels, dtype=np.float32)

    finite_mask = np.isfinite(image)
    valid_mask &= finite_mask

    valid_pixels = image[valid_mask]

    # 如果排除填充值后没有有效像素，退回全部有限像素。
    if valid_pixels.size == 0:
        valid_mask = finite_mask
        valid_pixels = image[valid_mask]

    if valid_pixels.size == 0:
        raise ValueError("图像中不存在有效像素。")

    lower_value = float(
        np.percentile(valid_pixels, lower_percentile)
    )
    upper_value = float(
        np.percentile(valid_pixels, upper_percentile)
    )

    # 极端情况下百分位范围无效，退回最小值和最大值。
    if not np.isfinite(lower_value) or not np.isfinite(upper_value):
        lower_value = float(np.min(valid_pixels))
        upper_value = float(np.max(valid_pixels))

    if upper_value <= lower_value:
        lower_value = float(np.min(valid_pixels))
        upper_value = float(np.max(valid_pixels))

    if upper_value <= lower_value:
        output = np.zeros(image.shape, dtype=np.uint8)
    else:
        clipped = np.clip(image, lower_value, upper_value)
        normalized = (
            (clipped - lower_value)
            / (upper_value - lower_value)
        )
        output = np.round(normalized * 255.0).astype(np.uint8)

    photometric = str(
        getattr(ds, "PhotometricInterpretation", "")
    ).upper()

    # 将 MONOCHROME1 统一转换为常规 PNG 显示：
    # 低值为黑，高值为白。
    if photometric == "MONOCHROME1":
        output = 255 - output

    # 无效区域统一设为黑色，避免填充区干扰训练。
    output[~valid_mask] = 0

    metadata = {
        "photometric": photometric or "MISSING",
        "rows": int(getattr(ds, "Rows", output.shape[0])),
        "columns": int(getattr(ds, "Columns", output.shape[1])),
        "bits_allocated": getattr(ds, "BitsAllocated", ""),
        "bits_stored": getattr(ds, "BitsStored", ""),
        "pixel_representation": getattr(ds, "PixelRepresentation", ""),
        "number_of_frames": getattr(ds, "NumberOfFrames", 1),
        "has_pixel_padding": hasattr(ds, "PixelPaddingValue"),
        "has_window": (
            hasattr(ds, "WindowCenter")
            and hasattr(ds, "WindowWidth")
        ),
        "has_rescale": (
            hasattr(ds, "RescaleSlope")
            or hasattr(ds, "RescaleIntercept")
        ),
        "lower_value": lower_value,
        "upper_value": upper_value,
        "output_min": int(output.min()),
        "output_max": int(output.max()),
    }

    return output, metadata


def save_png(image: np.ndarray, output_path: Path) -> None:
    """将二维 uint8 数组保存为无损灰度 PNG。"""
    if image.dtype != np.uint8:
        raise TypeError(f"保存前图像类型必须是 uint8，当前为 {image.dtype}")

    if image.ndim != 2:
        raise ValueError(f"保存前图像必须是二维灰度图，当前为 {image.shape}")

    output_path.parent.mkdir(parents=True, exist_ok=True)

    pil_image = Image.fromarray(image, mode="L")
    pil_image.save(
        output_path,
        format="PNG",
        compress_level=PNG_COMPRESSION_LEVEL,
        optimize=False,
    )


def convert_one_dicom(
    dicom_path: Path,
    input_root: Path,
    output_root: Path,
) -> tuple[str, Optional[dict[str, object]], Optional[str], Path]:
    """
    转换单个 DICOM。

    返回：
    status: converted / skipped / failed
    metadata: 成功时的元数据
    error: 失败原因
    output_path: 对应输出路径
    """
    output_path = get_output_path(
        dicom_path,
        input_root,
        output_root,
    )

    if output_path.exists() and not OVERWRITE_EXISTING:
        return "skipped", None, None, output_path

    try:
        ds = pydicom.dcmread(
            dicom_path,
            force=FORCE_READ_DICOM,
        )

        image, metadata = normalize_dicom_to_uint8(ds)
        save_png(image, output_path)

        return "converted", metadata, None, output_path

    except Exception as exc:
        return "failed", None, str(exc), output_path


def write_csv(
    csv_path: Path,
    rows: list[dict[str, object]],
    fieldnames: list[str],
) -> None:
    """写入 UTF-8-SIG CSV，便于直接用 Excel 打开。"""
    csv_path.parent.mkdir(parents=True, exist_ok=True)

    with csv_path.open(
        "w",
        newline="",
        encoding="utf-8-sig",
    ) as file:
        writer = csv.DictWriter(file, fieldnames=fieldnames)
        writer.writeheader()
        writer.writerows(rows)
```

```powershell
from pathlib import Path

import cv2
import numpy as np
import tifffile


def normalize_to_uint8(
    image: np.ndarray,
    lower_percentile: float = 0.5,
    upper_percentile: float = 99.5,
    invert: bool = False,
) -> np.ndarray:
    """将任意位深灰度图按百分位窗宽映射到 uint8。"""

    image = np.asarray(image)

    if image.ndim == 3:
        if image.shape[-1] == 3:
            image = cv2.cvtColor(image, cv2.COLOR_RGB2GRAY)
        else:
            image = image.squeeze()

    image = image.astype(np.float32)

    valid = image[np.isfinite(image)]
    if valid.size == 0:
        raise ValueError("图像中不存在有效像素。")

    lower = np.percentile(valid, lower_percentile)
    upper = np.percentile(valid, upper_percentile)

    if upper <= lower:
        raise ValueError(
            f"灰度范围无效：lower={lower}, upper={upper}"
        )

    image = np.clip(image, lower, upper)
    image = (image - lower) / (upper - lower)

    if invert:
        image = 1.0 - image

    return np.round(image * 255.0).astype(np.uint8)


def convert_tiff_to_png(
    source_path: Path,
    output_path: Path,
    use_clahe: bool = False,
) -> None:
    image = tifffile.imread(source_path)

    image_8bit = normalize_to_uint8(
        image,
        lower_percentile=0.5,
        upper_percentile=99.5,
        invert=False,
    )

    # 不建议默认永久使用 CLAHE。
    # 可以先关闭，后续作为训练增强动态应用。
    if use_clahe:
        clahe = cv2.createCLAHE(
            clipLimit=2.0,
            tileGridSize=(8, 8),
        )
        image_8bit = clahe.apply(image_8bit)

    output_path.parent.mkdir(parents=True, exist_ok=True)

    success = cv2.imwrite(
        str(output_path),
        image_8bit,
        [cv2.IMWRITE_PNG_COMPRESSION, 3],
    )

    if not success:
        raise RuntimeError(f"保存失败：{output_path}")
```

##### 一、DINOv2 官方到底使用什么格式
DINOv2 官方代码针对不同规模的数据集，提供了两种形式。

###### 1. ImageNet-1K：直接读取图片
DINOv2 官方给出的 ImageNet-1K 目录是：

```plain
<ROOT>/
├── train/
│   ├── n01440764/
│   │   ├── n01440764_10026.JPEG
│   │   └── ...
│   ├── n01443537/
│   └── ...
├── val/
│   ├── n01440764/
│   └── ...
├── test/
│   └── ...
└── extra/
    ├── entries-TRAIN.npy
    ├── entries-VAL.npy
    ├── entries-TEST.npy
    ├── class-ids-TRAIN.npy
    ├── class-ids-VAL.npy
    ├── class-names-TRAIN.npy
    └── class-names-VAL.npy
```

官方在生成元数据时使用了 `torchvision.datasets.ImageFolder`，训练读取时则根据 `entries-TRAIN.npy` 找到对应图像路径，再直接执行：

```python
with open(image_full_path, mode="rb") as f:
    image_data = f.read()
```

也就是说，**DINOv2 官方的 ImageNet-1K 训练入口就是直接读取单张 JPEG 图片，不是 tar。** ([GitHub](https://github.com/facebookresearch/dinov2))

###### 2. ImageNet-22K：使用 tar
DINOv2 官方对约 1180 万张图像的 ImageNet-22K 使用了 tar。其组织逻辑大致是：

```plain
<ROOT>/
├── n00001740.tar
├── n00001930.tar
├── n00002137.tar
├── ...
├── imagenet21kp_train.txt
├── imagenet21kp_val.txt
└── ...
```

这里不是常见的 WebDataset：

```plain
train-000000.tar
train-000001.tar
```

而是大致采用：

一个 ImageNet 类别对应一个 tar，通过预先保存的开始和结束字节偏移，使用 `mmap` 从 tar 中随机读取指定图像。

官方代码明确包含：

```python
def _get_tarball_path(class_id: str) -> str:
    return f"{class_id}.tar"
```

以及：

```python
mmap(tarball)
```

因此，DINOv2 的 ImageNet-22K 确实使用 tar，但这是为 **上千万张图像**设计的专用随机读取实现，不是普通 WebDataset 分片。 ([GitHub](https://github.com/facebookresearch/dinov2/blob/main/dinov2/data/datasets/image_net_22k.py?utm_source=chatgpt.com))

###### DINOv2 官方格式总结
| 数据集 | 规模 | 官方读取方式 |
| --- | --- | --- |
| ImageNet-1K | 128 万张 | 直接读取图片 |
| ImageNet-22K | 约 1180 万张 | 每类一个 tar，mmap 加偏移索引 |
| LVD-142M | 1.42 亿张 | 大规模内部数据管线，完整格式未公开 |


所以，不能简单地说：

DINOv2 官方就是用 tar 训练。

准确说法是：

DINOv2 官方对 ImageNet-1K 直接读取图片，对 ImageNet-22K 使用定制 tar 随机读取方案。

##### 四、你的 `shards/` 又是什么格式

```plain
...
```

特点通常是：

+ 每个 tar 保存固定数量的样本；
+ 每个样本通过相同 key 关联；
+ 流式读取；
+ 通过 WebDataset 或自定义 tar Dataset 读取。

比如 tar 内部可能是：

```plain
000000002.json
```

##### 五、你现在应该用哪一种
###### 我的明确建议：先直接读取 PNG
你的第一版预训练建议使用：

```plain
SpinePretrain-v1/spine_dino_dataset/train/spine/*.png
```

理由如下。

###### 1. 7 万张还没有达到必须 tar 的规模
DINOv2 官方对 128 万张 ImageNet-1K 都支持直接读取图片。

你的数据只有约 7 万张，相当于 ImageNet-1K 的约 5.5%。仅从文件数量看，没有必须打包为 tar 的必要。

###### 2. 你需要先保证训练逻辑正确
在正式追求吞吐量之前，更重要的是确认：

+ 每张图片都能读取；
+ 灰度映射正确；
+ RGB 通道转换正确；
+ DINOv2 多裁剪增强正确；
+ 分布式采样没有重复或遗漏；
+ epoch 长度正确；
+ 模型能正常保存和恢复；
+ 没有损坏图像；
+ 不同数据来源比例正确。

直接图片更容易定位问题。

###### 3. tar 不会消除 PNG 解码开销
tar 主要减少的是：

+ 文件系统元数据访问；
+ 大量文件打开和关闭；
+ 小文件随机寻址开销。

但无论是否放入 tar，里面仍然是 PNG，CPU 仍然需要执行 PNG 解码。

医学图像 PNG 通常分辨率较高，真正的瓶颈可能是：

+ PNG 解码；
+ 随机裁剪；
+ Resize；
+ 多个 global/local crops；
+ CPU worker 数不足。

单纯打包 tar 不一定会显著加速。

###### 4. 直接图片更符合你当前修改版 DINOv2
你的目录已经包含：

```plain
image_files-TRAIN.npy
class-ids-TRAIN.npy
class-names-TRAIN.npy
```

这说明 Codex 已经围绕图片目录建立了索引。继续使用这套方案改动最小。

##### 六、什么时候再切换 tar
出现以下情况时，再考虑使用 `shards/`：

+ 数据放在 NFS、NAS 或网络共享盘；
+ 数据放在机械硬盘；
+ 八卡训练时 GPU 利用率频繁下降；
+ `nvidia-smi` 中 GPU 利用率呈周期性锯齿；
+ DataLoader 等待时间明显；
+ 增加 `num_workers` 后仍无法改善；
+ 每次 epoch 开始时文件扫描很慢；
+ 图片数量未来扩展到几十万或上百万。

正式决定前，建议对两套读取器做相同条件的吞吐量测试：

```plain
图片目录：images/s
tar 分片：images/s
```

测试时固定：

+ batch size；
+ `num_workers`；
+ 图像增强；
+ GPU 数量；  
-训练步数；
+ 缓存状态。

不要只测试“纯读取”，应测试完整 DINOv2 augmentation，因为模型实际运行时每张原图会生成多个 crop。

##### 七、推荐保留当前双格式结构
你现在这个结构其实很好，不建议删除任何一套：

```plain
SpinePretrain-v1/
├── spine_dino_dataset/    # 默认训练和排错
├── shards/                # 性能优化、迁移和备选训练入口
└── metadata/              # 数据追踪、审计和统计
```

推荐职责是：

| 目录 | 用途 |
| --- | --- |
| `spine_dino_dataset` | 当前正式训练入口 |
| `shards` | 后续 WebDataset 性能实验 |
| `manifest.csv` | 每张图像的来源、路径和属性 |
| `excluded.csv` | 被排除图像及原因 |
| `shards.csv` | 每个样本所属分片 |
| `build_report.json` | 构建过程统计 |


最终选择是：

**第一阶段直接从 **`**spine_dino_dataset**`** 读取 PNG；保留 tar，但暂时不作为默认训练输入。**

这与 DINOv2 和 RAD-DINO 的官方实践并不冲突。DINOv2 本身同时存在图片和 tar 两套实现，而 RAD-DINO明确将影像预处理并保存为 PNG。你当前最需要检查的不是“要不要 tar”，而是 Codex 修改后的 Dataset 类是否正确识别 `image_files-TRAIN.npy`、是否支持任意数据集长度，以及多 GPU 下是否使用了正确的 DistributedSampler。
